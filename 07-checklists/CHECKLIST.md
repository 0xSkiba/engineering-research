# Практический чеклист

> Для соло-разработчика с AI-агентами. Отмечайте `[x]`. Обоснования и источники — в разделах 01–06. Пункты помечены: 🔴 обязательно до запуска, 🟡 до роста, ⚪ когда понадобится.

## A. Каждый PR (в т.ч. от агента)
- [ ] 🔴 PR маленький, одна цель; описание: что, зачем, как проверено, как откатить
- [ ] 🔴 Typecheck, линтер, тесты зелёные; тесты не удалены и не ослаблены
- [ ] 🔴 Новые эндпоинты: authz по владельцу/tenant + тест «чужой → 404»
- [ ] 🔴 Внешний ввод валидируется схемой (`.strict()`)
- [ ] 🔴 Нет секретов в диффе (gitleaks/push protection)
- [ ] 🔴 Новые зависимости проверены (существует, репутация, не typosquat) и обоснованы
- [ ] 🟡 Изменения схемы БД — expand/contract, индексы CONCURRENTLY
- [ ] 🟡 Новое поведение — за feature flag
- [ ] 🟡 Перечитан дифф целиком (агенты добавляют лишнее: отключённые проверки, `any`, моки в проде)

## B. Репозиторий и CI
- [ ] 🔴 Branch protection на `main`: PR + зелёный CI
- [ ] 🔴 Secret scanning + push protection; gitleaks в pre-commit
- [ ] 🔴 Lockfile в git, `npm ci`/frozen-lockfile
- [ ] 🔴 GitHub Actions: пиннинг по SHA, минимальные `permissions`, нет `${{ github.event.* }}` в `run:`
- [ ] 🔴 Dependabot security updates
- [ ] 🟡 OIDC вместо статических облачных ключей
- [ ] 🟡 SAST (Semgrep/CodeQL) в CI
- [ ] ⚪ Подпись/provenance для публикуемых пакетов

## C. Аутентификация и сессии
- [ ] 🔴 Готовая библиотека/провайдер, не самописная
- [ ] 🔴 Argon2id/bcrypt; проверка по утёкшим паролям; без правил состава
- [ ] 🔴 Cookie `HttpOnly; Secure; SameSite`; CSRF-защита
- [ ] 🔴 Лимиты на login/reset по аккаунту + IP + подсети; Turnstile
- [ ] 🔴 2FA/passkey для админки; 2FA-ключи на GitHub, npm, облаке, регистраторе, Cloudflare
- [ ] 🟡 Повторная аутентификация для чувствительных действий
- [ ] 🟡 Аудит активных сессий/токенов/OAuth-приложений раз в квартал

## D. Данные и БД
- [ ] 🔴 БД/Redis/хранилища не в публичной сети; S3 Block Public Access
- [ ] 🔴 Бэкапы автоматически + **проверенное восстановление** (дата последнего теста: ____)
- [ ] 🔴 `tenant_id`/`owner_id` в таблицах с клиентскими данными; RLS как второй рубеж
- [ ] 🔴 Приложение под ролью без BYPASSRLS и не владельцем таблиц
- [ ] 🔴 Деньги — bigint/Decimal; атомарные обновления балансов
- [ ] 🟡 Пулинг соединений (PgBouncer/встроенный)
- [ ] 🟡 `pg_stat_statements` + алерт на медленные запросы
- [ ] 🟡 UUIDv7/ULID для ID; 64-битные ID строкой в JSON
- [ ] 🟡 Audit log append-only для действий с данными клиентов
- [ ] ⚪ Реплики для чтения → кэш → партиционирование → (только потом) шардирование

## E. API и веб
- [ ] 🔴 Rate limit на всех публичных эндпоинтах + лимит тела + максимум пагинации
- [ ] 🔴 SQL параметризован; нет `eval`/`exec` со строкой/`innerHTML` с внешними данными
- [ ] 🔴 SSRF-guard для любых запросов по пользовательскому URL
- [ ] 🔴 Ошибки не раскрывают стек и внутренности; fail-closed
- [ ] 🔴 Security headers: CSP, HSTS, `X-Content-Type-Options`, `frame-ancestors`
- [ ] 🟡 Идемпотентные ключи для операций с побочными эффектами
- [ ] 🟡 Таймауты на всех исходящих запросах; ретраи с jitter
- [ ] 🟡 Версионирование API; инвентарь эндпоинтов (что публично)

## F. Защита от ботов и абуза
- [ ] 🔴 Edge rate limiting (Cloudflare) на signup/login/API
- [ ] 🔴 Turnstile на signup/login с серверной проверкой Siteverify
- [ ] 🔴 Email-подтверждение до доступа к API; блок одноразовых доменов; канонический email
- [ ] 🔴 Глобальный лимит на каждый дорогой эндпоинт
- [ ] 🟡 Лимиты по IP + подсети + fingerprint + аккаунту
- [ ] 🟡 Квоты по уровню доверия (возраст, верификация, оплата)
- [ ] 🟡 Стоимостные лимиты для тяжёлых запросов
- [ ] 🟡 Velocity-алерты на регистрации (по подсети, домену, времени)
- [ ] ⚪ Риск-скор + challenge/shadow; офлайн-кластеризация аккаунтов
- [ ] ⚪ API-ключи с квотами по тарифам

## G. Релизы и эксплуатация
- [ ] 🔴 Health-check, структурированные логи с request id, алерты на 5xx/задержку
- [ ] 🔴 Быстрый откат (предыдущая версия разворачивается одной командой)
- [ ] 🟡 Staging/preview с похожими данными (без реальных PII)
- [ ] 🟡 Feature flags с kill switch
- [ ] 🟡 Изменения конфигурации раскатываются постепенно
- [ ] 🟡 1–2 SLO (доступность, задержка) и error budget
- [ ] ⚪ Постмортем-шаблон; ведение журнала инцидентов

## H. Смарт-контракты и кошельки
- [ ] 🔴 Ключи деплоя/админа на аппаратных кошельках; никогда в `.env`/CI/агенте
- [ ] 🔴 Админ = мультисиг (независимые устройства) + timelock
- [ ] 🔴 OZ роли, CEI, ReentrancyGuard, пауза, лимиты вывода
- [ ] 🔴 Оракулы: staleness, границы, часы торгов для RWA
- [ ] 🔴 Slither + Foundry fuzz/invariant; внешний аудит до реальных средств
- [ ] 🔴 Проверка calldata на независимом устройстве перед подписью
- [ ] 🟡 Upgradeable: `_disableInitializers()`, проверка storage layout, тест апгрейда на форке
- [ ] 🟡 Мониторинг событий контракта и алерты на аномальные выводы
- [ ] 🟡 Bug bounty
- [ ] 🟡 Фронтенд: CSP+SRI, registrar lock, DNSSEC, мониторинг DNS и бандла

## I. Право и приватность (не юридическая консультация)
- [ ] 🔴 Privacy policy отражает реальные данные (включая IP/fingerprint для антифрода)
- [ ] 🟡 Карта персональных данных: что, где, зачем, сколько хранится
- [ ] 🟡 Процесс удаления/экспорта данных по запросу (GDPR ст. 15/17)
- [ ] 🟡 План уведомления об утечке (GDPR: регулятору в течение 72 ч)
- [ ] 🟡 Консультация юриста по GDPR/крипто-регулированию в ваших юрисдикциях

## J. Инцидент (когда что-то сломалось или утекло)
- [ ] Остановить кровотечение: откат / feature flag off / пауза контракта / блок на edge
- [ ] Ротировать утёкшие секреты (не только удалить из git)
- [ ] Сохранить логи и таймлайн (UTC)
- [ ] Сообщить пользователям/регулятору, если затронуты данные (с юристом)
- [ ] Blameless постмортем: что случилось, почему, что меняем (с владельцем и сроком)

## Что делать / чего не делать

**Делать**
- Пройти 🔴 пункты до запуска; 🟡 — до первых платящих клиентов или роста трафика.
- Возвращаться к разделу A на каждом PR, к остальным — раз в квартал.

**Не делать**
- Не пытаться закрыть всё сразу: ⚪ пункты без реальной нагрузки — лишняя сложность.
- Не отмечать пункт, если он не проверен на практике (например, восстановление из бэкапа).
