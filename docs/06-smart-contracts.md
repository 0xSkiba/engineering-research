# Смарт-контракты: дополнительные требования

**[Факт; S17]** Документация Solidity рассматривает reentrancy, ограничения gas/циклов и опасность авторизации через tx.origin. **[Факт; S09]** Публичный аудит Uniswap фиксирует конкретные версии и находки. Ниже — **[Рекомендации]**, а не гарантия безопасности контракта.

| Риск | Что проверять |
|---|---|
| Повторный вход | Внешние вызовы, порядок изменения состояния, межфункциональные инварианты |
| Права администратора | Кто может обновлять код, выводить средства, менять oracle и комиссии |
| Бесконечный рост работы | Нет критической функции с обходом всех пользователей |
| Oracle | Свежесть, единицы, decimals, границы и поведение при недоступности |
| Slippage/deadline | Проверка итогового результата и времени исполнения |
| Подписи | Nonce, domain separation, chain/contract, deadline и replay |
| Token semantics | Необычные ERC-20, fee-on-transfer, округление, возвращаемые значения |
| Upgrade | Совместимость storage, инициализация и полномочия обновления |
| Экономика | Инварианты обеспечения, расчёт комиссий, возможность манипуляции входами |

Эти вопросы не имеют одного правильного решения для всех протоколов. Например, pause и upgrade могут ограничить ущерб, но добавляют доверие к управляющим ключам; неизменяемый контракт не получает простой rollback.

## Проверка до mainnet

Зафиксировать scope и модель доверия. Записать инварианты, например: нельзя вывести больше принадлежащего пользователю; сумма обязательств согласуется с учётом активов по правилам протокола. Прогнать unit, fuzz/property и invariant-тесты; проверить интеграцию с внешними контрактами на подходящем fork. Затем независимая проверка и закрытие находок с повторной проверкой фиксов.

Сохранить версию компилятора, настройки сборки, исходники, commit и параметры deployment. После развёртывания сверить bytecode/верификацию и фактические права. Настроить наблюдение событий, отклонений и действий администраторов. Bug bounty дополняет проверки, но не заменяет их.

## Связь с примером про ботов

Rate limit сайта ограничивает сайт. Permissionless-контракт может вызываться напрямую. Если критично ограничить claim, mint, бонус или иной ресурс, правило должно обеспечиваться самим протоколом либо явно доверенным механизмом авторизации. Один адрес не равен одному человеку. Проверка UI не защищает on-chain инвариант.

Платёж gas также не доказывает добросовестность: операция может оставаться выгодной атакующему. При проектировании оценивайте прибыль/стоимость злоупотребления и ущерб другим участникам.
