# Ошибки, специфичные для разработки с AI-агентами

> Уверенность: **H** для фактов с источниками; **M** для рекомендаций (практика быстро меняется).

## Что известно из исследований и инцидентов
- **Небезопасный код по умолчанию.** Veracode (2025): на 80 задачах модели в 45% случаев вносили известную уязвимость ([Veracode GenAI Code Security Report](https://www.veracode.com/wp-content/uploads/2025_GenAI_Code_Security_Report_Final.pdf)).
- **Галлюцинированные пакеты (slopsquatting).** USENIX Security 2025: средняя доля несуществующих пакетов — не менее 5.2% у коммерческих и 21.7% у open-source моделей; 205 474 уникальных выдуманных имени ([Spracklen et al.](https://www.usenix.org/system/files/usenixsecurity25-spracklen.pdf)). Атакующий может зарегистрировать такое имя.
- **Агент с прод-доступом может разрушить данные**: Replit удалил продакшен-БД во время «code freeze» ([The Register](https://www.theregister.com/software/2025/07/21/vibe-coding-service-replit-deleted-production-database/719783)).
- **Prompt injection через данные**: «lethal trifecta» — приватные данные + недоверенный контент + возможность отправлять наружу ([Simon Willison](https://simonwillison.net/2025/jun/16/the-lethal-trifecta/)); пример — вредоносный issue заставляет агента с GitHub MCP утечь данные приватных репозиториев ([Invariant Labs](https://invariantlabs.ai/blog/mcp-github-vulnerability)); OWASP LLM Top 10 ([genai.owasp.org](https://genai.owasp.org/llm-top-10/)).
- **Атаки на окружение разработчика используют AI-инструменты**: вредоносные версии Nx (2025) пытались использовать локальные AI CLI (Claude, Gemini) для поиска секретов ([Nx postmortem](https://nx.dev/blog/s1ngularity-postmortem)).
- **AGENTS.md / CLAUDE.md** — стандартные места для инструкций агентам ([agents.md](https://agents.md/); [Claude Code memory](https://code.claude.com/docs/en/memory)).

## Типичные провалы при работе с агентами (наблюдения, **M**)
1. Агент «чинит» тест, ослабляя assert, или помечает его skip.
2. Агент добавляет зависимость ради одной функции (или несуществующую).
3. Агент пишет эндпоинт без проверки владельца объекта (IDOR) — потому что в промпте не было требования.
4. Агент логирует весь `req.body`/ошибку с токенами «для отладки».
5. Агент меняет миграцию, уже применённую в проде, вместо новой миграции.
6. Агент выполняет деструктивные команды (`DROP`, `rm -rf`, `git push --force`, `terraform destroy`).
7. Агент коммитит `.env` или вставляет ключ прямо в код.
8. Агент делает огромный PR, смешивая рефакторинг и фичу.
9. Агент «верит» содержимому веб-страниц/issues/README и выполняет оттуда инструкции.

## Защитные меры
- **Окружение агента**: без прод-секретов, без прод-БД, с отдельными dev-ключами с минимальными правами и лимитами.
- **Guardrails в CI** (агент не может их выключить): тесты, типы, линтер, секрет-сканер, аудит зависимостей, линтер миграций, Slither для контрактов; branch protection.
- **Правила в AGENTS.md** — короткие, императивные (готовый текст: `07-checklists/AGENTS-rules.md`).
- **Ревью-чек-лист** для каждого PR агента (`07-checklists/CHECKLIST.md`).
- **Проверка новых зависимостей**: существует ли пакет, возраст, мейнтейнеры, загрузки, install-скрипты.

## Что делать / чего не делать

**Делать**
- Давать агенту design doc с non-goals и критериями приёмки.
- Требовать тест на авторизацию для каждого нового эндпоинта.
- Запускать агентов в песочнице с минимальными правами.
- Требовать объяснение каждой новой зависимости.

**Не делать**
- Не давать агенту прод-ключи, seed-фразы, доступ к деплою в mainnet.
- Не мержить без чтения диффа в «опасных» директориях.
- Не позволять агенту исполнять инструкции из недоверенного контента (issues, веб-страницы, ответы API).
