# Офчейн-боты и инфраструктура: ключи, RPC, nonce, идемпотентная отправка, reorgs

> Уверенность: **H** для фактов о взломах (постмортемы, ФБР, Sygnia); **M** для инженерных рекомендаций — общепринятая практика, конкретные числа подбирать под свой стек.
> Для торговых/арбитражных/grid-ботов на Solana и EVM. Контракты — в [`05-crypto-specific.md`](05-crypto-specific.md) и [`../02-by-product-type/04-smart-contracts.md`](../02-by-product-type/04-smart-contracts.md).

## Ключи
- Приватный ключ бота — не в git, не в коде, не в `.env` на ноутбуке, не в промпте агента. Варианты по возрастанию надёжности: `.env` на сервере с правами `600` и без доступа агента → secrets manager (Doppler/Infisical/SOPS+age) → отдельный **signer-сервис** (бот готовит транзакцию, подписывает другой процесс с ключом в памяти) → KMS/HSM.
- **Горячий кошелёк с минимальным балансом**: столько, сколько нужно на сутки работы. Остальное — на холодном/мультисиге. Пополнение по алерту.
- Лимиты на уровне бота: максимум на одну транзакцию, максимум за час, whitelist адресов вывода, kill switch (флаг в Redis, который бот проверяет перед каждой отправкой).
- Отдельные ключи на каждый бот/стратегию: компрометация одного не кладёт всё.
- Ротация: умейте за 10 минут вывести всё с ключа и поднять новый. Запишите runbook.

## RPC
- 2–3 провайдера (свой нод + Helius/Triton/QuickNode для Solana; Alchemy/Infura/свой для EVM) с **фолбэком** и health-check; таймауты на каждый вызов (`AbortSignal.timeout(5000)`), экспоненциальный backoff с jitter, обработка `429`.
- Публичные RPC — только для dev. Платные ключи — только на сервере, никогда в `NEXT_PUBLIC_*`.
- Разделяйте RPC для чтения (можно кэшировать, реплика) и для отправки (критичный путь).
- Логируйте latency по провайдеру; переключайтесь автоматически по p99 и доле ошибок.

## Nonce (EVM)
- **Одна очередь на кошелёк**: все отправки с одного адреса идут через единственный worker, который держит счётчик nonce в памяти и синхронизирует с `getTransactionCount('pending')` после ошибок.
- Застрявшая транзакция — замена с **тем же nonce** и большим газом (`maxPriorityFeePerGas` +10–20%), а не новая транзакция.
- Два процесса на одном ключе — гарантированные `nonce too low` / `replacement underpriced`. Если нужны параллельные отправки — несколько кошельков.

## Идемпотентная отправка
- **Solana:** подпись транзакции = её ID. Сохраняйте подпись в БД **до** отправки (`status = 'sending'`), ретраите ту же сериализованную транзакцию до истечения `blockhash` (~60–90 с), потом проверяйте `getSignatureStatuses`. Не пересобирайте транзакцию с новым blockhash, пока не убедились, что старая не прошла.
- **EVM:** то же с `(address, nonce)` как ключом идемпотентности. Хэш транзакции сохраняется до `sendRawTransaction`.
- Паттерн БД: таблица `tx_intents (id, idempotency_key UNIQUE, chain, payload, status, tx_hash, created_at)`; переход статусов `pending → sent → confirmed | failed`; воркер при рестарте дочитывает `sent` и сверяет с цепочкой. См. Idempotency-Key у Stripe ([blog](https://stripe.com/blog/idempotency)).

## Подтверждения и reorgs
- **Solana:** `processed` — для UI, `confirmed` — для логики бота, `finalized` — для зачисления средств и всего необратимого.
- **EVM:** зачисление после N блоков (L1: 12+, L2 — по документации сети и статусу батча на L1). Обработка событий идемпотентна по `(tx_hash, log_index)`; при reorg — откат по `block_hash`.
- Индексер хранит `block_hash` каждого обработанного блока и при несовпадении родителя откатывает хвост.

## Исполнение: slippage, MEV, цены
- Всегда `minAmountOut` / slippage + `deadline`; на Solana — compute budget и priority fee по текущему рынку.
- Отправка через Flashbots Protect / приватные mempool-ы (EVM) и Jito bundles (Solana) для чувствительных к MEV сделок.
- Цена из одного пула — не оракул (Mango, Inverse, Cream, Harvest — см. [`06-crypto-hack-postmortems.md`](06-crypto-hack-postmortems.md)). Для RWA-перпов проверяйте свежесть и торговые часы эталонного рынка.
- Все суммы — `bigint` в минимальных единицах с decimals токена рядом (USDC 6, ETH 18, SOL 9). Брендированные типы: `type Lamports = bigint & { __brand: 'lamports' }`.

## Мониторинг бота
- Алерты в Telegram: баланс горячего кошелька ниже порога, ошибка подписи/отправки N раз подряд, расхождение ожидаемого и фактического баланса, тишина бота > X минут, крупный вывод.
- Метрики: сделок/час, PnL, доля failed транзакций, latency RPC по провайдеру, глубина очереди отправки.
- Отдельный «сторож»: процесс, который сравнивает on-chain баланс с учётным и останавливает бота при расхождении.

## Уроки взломов (дополнение к таблице в 06)
| Инцидент | Что произошло | Lesson |
|---|---|---|
| **The DAO, 2016** (~3,6 млн ETH) | Reentrancy в `splitDAO`: вывод до обновления баланса → хардфорк Ethereum | Сначала обновляйте состояние, потом внешний вызов (CEI) |
| **Wormhole, 02.2022** (~$326 млн) | На Solana обошли проверку подписей гардианов через устаревшую функцию и сминтили 120 000 wETH без депозита; **фикс уже лежал в репозитории, но не был задеплоен** | Проверяйте каждый переданный аккаунт; деплойте security-фиксы немедленно, не «со следующим релизом» |
| **Ronin, 03.2022** (~$625 млн) | Lazarus получил 5 из 9 ключей валидаторов: 4 через инфраструктуру Sky Mavis + 1 через **забытое делегирование** от Axie DAO; взлом заметили через 6 дней | Считайте **независимых** владельцев ключей; отзывайте временные разрешения; алерт на крупные выводы |
| **Nomad, 08.2022** (~$190 млн) | При апгрейде доверенный root инициализировали `0x00` — любое сообщение считалось доказанным; сотни адресов копировали транзакцию атакующего | `require(root != bytes32(0))`; тестируйте апгрейды на форке mainnet |
| **Euler, 03.2023** (~$197 млн) | Новая `donateToReserves` не вызывала проверку ликвидности → самоликвидация | Каждая новая функция обязана соблюдать системные инварианты; аудируйте изменения, не только v1 |
| **Bybit, 21.02.2025** (~$1,5 млрд, крупнейшая кража в истории крипты) | Lazarus скомпрометировал машину разработчика Safe{Wallet}, подменил JS фронтенда в AWS S3; подписанты одобрили транзакцию, выглядевшую как обычный перевод, но менявшую логику кошелька; ФБР подтвердило атрибуцию к КНДР | Независимо декодируйте calldata на аппаратном кошельке / втором устройстве; whitelist адресов и задержки для крупных переводов |

Сквозной вывод: по сумме потерь **ключи, подписанты и фронтенд** бьют баги контрактов. Для бота это значит: угрозы моделировать сначала для ключа и машины, на которой он живёт.

## Что делать / чего не делать

**Делать**
- Signer отдельно от стратегии; горячий баланс — минимальный; kill switch и whitelist.
- Один воркер на кошелёк для nonce; идемпотентность по подписи/nonce; статусы в БД.
- 2–3 RPC с фолбэком и таймаутами; `finalized` для необратимого.

**Не делать**
- Не давать AI-агенту ключ, seed или доступ к деплою в mainnet.
- Не пересобирать транзакцию «на всякий случай», пока не проверили статус старой.
- Не держать на горячем кошельке больше, чем готовы потерять за сутки.
